Accessory System

v1.0

Dynamic Character Accessories for Unity 6  ·  Render Pipeline Agnostic  ·  Runtime + Editor Tooling

Quick Start

Get an accessory appearing on a character in under 5 minutes.

Step 1 — Add components to your character

  1. Add ArchetypeTag — set at least one tag matching your character type, e.g. humanoid-male
  2. Add AccessorySocketMap — add one entry: Slot Config = your SlotConfig asset, Bone Name = exact bone name from your rig (e.g. mixamorig:Head). Use the Pick button to scan your hierarchy and select from a list.
  3. Add AccessoryController — no manual configuration needed. Reads ArchetypeTag and AccessorySocketMap automatically.

Step 2 — Create your data assets

Right-click in Project window → Create → Accessory System

  1. Create a Slot Config — give it a unique Slot ID like LeftEar or Neck
  2. Create an Accessory Variant Definition — set archetype tag, assign SlotConfig, assign prefab, enter bone name
  3. Create an Accessory Item — give it a unique Item ID and add the variant to its Variants list

Step 3 — Position the accessory visually

  1. Select your character in the Scene
  2. In the AccessorySocketMap Inspector scroll to Variant Preview
  3. Assign your Variant Definition — the mesh appears on the character in edit mode
  4. Toggle Position / Rotation / Scale handles and drag to place precisely
  5. Values write back to the Variant SO automatically with full Undo support

Step 4 — Equip at runtime

var controller = character.GetComponent<AccessoryController>();

controller.Equip(myItem, mySlot);              // equip into slot
controller.Unequip(mySlot);                    // remove from slot
controller.Swap(newItem, mySlot);              // replace slot contents
AccessoryItem cur = controller.Query(mySlot);  // query current item

Step 5 — Subscribe to events

controller.OnEquip   += (item, slot) => Debug.Log($"Equipped {item.DisplayName}");
controller.OnUnequip += slot         => Debug.Log($"Unequipped {slot.SlotId}");
controller.OnSwap    += (item, slot) => Debug.Log($"Swapped to {item.DisplayName}");

Step 6 — Material variants (optional)

To support Black, Gold, Platinum versions of the same mesh:

  1. Add AccessoryMaterialVariant to your accessory prefab root
  2. Fill the Variants array — index 0 = Black, 1 = Gold, 2 = Platinum
  3. On each AccessoryVariantDefinition set Material Variant Index to the matching index. Set -1 to skip.
Important: Place AccessoryMaterialVariant on the prefab root even if renderers are on child GameObjects. The component uses GetComponentsInChildren and applies the material to every renderer and every material slot found — multi-mesh accessories update correctly in one call.

Runtime Components

All components live in AccessorySystem.Runtime. Add to character GameObjects unless noted.

ArchetypeTag required

Defines the character's identity with an ordered list of string tags. Most specific tag first.

FieldDescription
TagsOrdered archetype strings. E.g. ["humanoid-female", "humanoid"]
MethodDescription
AddTag(string)Add a tag at runtime for transformations or state changes
RemoveTag(string)Remove a tag at runtime
HasTag(string)Returns true if the character has the given tag
SetTags(IEnumerable)Replace all tags at once

AccessorySocketMap required

Maps slot labels to bone transforms. Walks the full hierarchy on Awake to cache bones by name. Call Initialize() manually if the rig changes at runtime.

Bone names must match exactly — including capitalisation and colons. Use the Bone Finder (Scan Hierarchy → Pick) to select from your actual rig bones rather than typing manually.

AccessoryController required

The main runtime engine. Implements IAccessoryEquippable. Resolves variants, instantiates prefabs, parents to bones, applies material variants, fires C# events. Requires ArchetypeTag and AccessorySocketMap on the same GameObject via [RequireComponent].

AccessoryJiggle optional — attach to prefab

Spring/damper secondary physics. Attach to the accessory prefab root, not the character.

FieldDescription
StiffnessReturn-to-rest strength. Range 0.1–50. Higher = stiffer.
DampingOscillation decay. Range 0.1–20. Higher = less swinging.
Max AngleMaximum sway in degrees. Prevents accessories flipping.
Velocity InfluenceHow strongly parent bone velocity drives sway. Range 0–5.
Sway X / Sway ZToggle which local axes are allowed to sway.

Call SnapToRest() after teleports. Call SetCurrentAsRest() after programmatic repositioning.

AccessorySaveModule optional

Persists equipped state to PlayerPrefs. Add alongside AccessoryController to enable. Omit to disable entirely.

FieldDescription
Character IDUnique save key prefix. Defaults to GameObject name if empty.
Tracked SlotsWhich SlotConfigs to persist.
Auto Save On ChangeSaves to PlayerPrefs on every equip/unequip/swap event.
Auto Load On StartRe-equips saved items on Start.
Item RegistryAll AccessoryItems that could be loaded. Required for resolving saved item IDs back to SO references.

AccessoryMaterialVariant optional — attach to prefab

Swaps materials across all renderers in the prefab hierarchy with a single call. Attach to the prefab root. Searches children automatically. Applies the chosen material to all material slots on every renderer found.

FieldDescription
VariantsArray of materials. Index 0 is the base material.
Default Variant IndexWhich index to show by default. Overridden at runtime by AccessoryController when MaterialVariantIndex is set on the Variant Definition.
var mat = accessory.GetComponent<AccessoryMaterialVariant>();
mat.ApplyVariant(0);            // by index
mat.ApplyVariant("Mat_Gold");   // by material name
mat.NextVariant();              // cycle through all variants

Data Assets

Right-click in Project window → Create → Accessory System

SlotConfig

Defines a named equipment slot. Fully developer-defined — no hardcoded slot types exist in the system.

FieldDescription
Slot IDUnique string identifier. E.g. LeftEar, RightEar, Neck, LeftWrist
Display NameHuman-readable label for UI. Falls back to Slot ID if empty.

AccessoryVariantDefinition

How a specific accessory looks on a specific character archetype in a specific slot. Create one per archetype-slot combination that needs a unique visual.

FieldDescription
Archetype TagMust exactly match a tag on the character's ArchetypeTag component.
Slot ConfigWhich slot this variant targets. Used by the slot-aware resolver.
Accessory PrefabPrefab instantiated and parented to the bone at runtime.
Bone NameExact bone name in the character's skeleton. E.g. mixamorig:Head
Local Position OffsetFine position offset from the bone. Set visually with the position handle.
Local Rotation OffsetFine rotation from the bone. Set with the rotation handle.
Local ScaleScale relative to default. Useful for sizing per character.
Material Variant IndexIndex into the prefab's AccessoryMaterialVariant. Applied after instantiation. Set to -1 to skip.
LOD 1 / LOD 2 PrefabOptional lower-detail prefabs. Leave empty if not needed.

AccessoryItem

Top-level logical identity of a wearable item. One per item in your game world. Holds all variants across all archetypes and slots.

FieldDescription
Item IDUnique string. Match your inventory system's item ID for easy bridging.
Display NameHuman-readable name for UI.
IconOptional Sprite for UI display.
VariantsList of AccessoryVariantDefinition assets. One per archetype-slot combination.
Slot-aware resolution: Resolver first matches archetype AND slot together. Falls back to archetype-only if no slot-specific variant exists. Necklaces work with one variant per character while earrings can have fully independent left and right variants on the same item.

Editor Tools

All editor tooling lives in AccessorySystem.Editor — never included in builds.

Bone Finder

Click Scan Hierarchy for Bones on the AccessorySocketMap Inspector to scan the full character transform tree. Click Pick on any socket entry to choose from the complete list. A green indicator confirms the bone name is valid in the current hierarchy. Red means the bone name doesn't match — check spelling and capitalisation.

Variant Preview

Assign a Variant Definition to the Preview Variant field. The accessory mesh appears on the character in edit mode at current offset values. Updates live as you drag handles. The preview instance is flagged HideFlags.DontSave — never saved into your scene.

Scene View Handles

Three toggleable handle types when a Variant Preview is active. Only one active at a time is recommended.

HandleControlsWrites to
PositionMove in local bone spaceLocal Position Offset
RotationRotate relative to boneLocal Rotation Offset
ScaleScale with minimum clamp (0.0001)Local Scale
All changes write directly to the Variant SO on disk at 4 decimal precision with full Undo/Redo. A live readout shows current values updating in real time as you drag. Reset buttons — Reset Pos, Reset Rot, Reset Scale, Reset All — are available while a preview is active.

Variant Definition Inspector

FeatureDescription
Precision fieldsPosition, rotation, scale shown at 4 decimal places with direct text entry
Material Variant IndexSet which material variant to apply when equipped. -1 skips swapping.
Reset OffsetsZero position/rotation, reset scale to 1,1,1 in one click
Copy Offset ValuesCopies all current offset values to clipboard as formatted text
Validation summaryGreen when all required fields are filled. Red lists exactly what is missing.

API Reference

IAccessoryEquippable

public interface IAccessoryEquippable
{
    // Equip item into slot. Unequips existing item in that slot first.
    void Equip(AccessoryItem item, SlotConfig slot);

    // Remove item from slot. No-op if slot is already empty.
    void Unequip(SlotConfig slot);

    // Replace slot contents. Fires OnSwap, not separate equip/unequip events.
    void Swap(AccessoryItem newItem, SlotConfig slot);

    // Returns item currently in slot, or null if empty.
    AccessoryItem Query(SlotConfig slot);
}

Integration Guide

Connecting your inventory system

public class MyInventoryBridge : MonoBehaviour, IAccessoryEquippable
{
    private AccessoryController _controller;
    void Awake() => _controller = GetComponent<AccessoryController>();

    public void Equip(AccessoryItem item, SlotConfig slot)
        => _controller.Equip(item, slot);
    public void Unequip(SlotConfig slot)
        => _controller.Unequip(slot);
    public void Swap(AccessoryItem item, SlotConfig slot)
        => _controller.Swap(item, slot);
    public AccessoryItem Query(SlotConfig slot)
        => _controller.Query(slot);
}

Adding stats or effects to accessories

[CreateAssetMenu(menuName = "My Game/My Accessory Item")]
public class MyAccessoryItem : AccessoryItem
{
    [SerializeField] private int fireResistanceBonus;
    [SerializeField] private Rarity rarity;

    public int    FireResistance => fireResistanceBonus;
    public Rarity Rarity         => rarity;
}
The system only reads the base AccessoryItem class. Your subclass fields are completely invisible to the attachment pipeline — safe to extend freely without touching the system.

Reacting from other systems

// Stat system recalculates on any equip change
controller.OnEquip   += (item, slot) => statSystem.Recalculate(character);
controller.OnUnequip += slot         => statSystem.Recalculate(character);

// Achievement unlock
controller.OnEquip += (item, slot) => {
    if (item.ItemId == "item_legendary_ring")
        achievements.Unlock("first_legendary");
};

Scripted equip from game logic

Call AccessoryController.Equip() directly from any coroutine, dialogue system, cutscene manager, or quest callback. The demo's StoryEquipTrigger shows a complete example with camera movement and configurable timing.

Render pipeline compatibility

The runtime system is render pipeline agnostic — it performs only transform manipulation and material assignment. Works identically with URP, HDRP, Built-in, and custom render pipelines. The demo scene uses URP/Lit materials. Reassign demo materials if using a different pipeline.

Frequently Asked Questions

Does this work with my existing inventory system?
Yes. Implement IAccessoryEquippable on a bridge component. Your inventory calls the bridge, the bridge calls Equip/Unequip. The system never needs to know how your inventory is structured.
Does it work with non-Mixamo rigs?
Yes. Any humanoid or creature rig works. Map bone names via AccessorySocketMap. The Bone Finder scans your hierarchy so you never need to type bone names manually.
What render pipelines are supported?
The runtime system is render pipeline agnostic. Demo scene uses URP materials. If using HDRP or Built-in, reassign the demo materials — the system requires no changes.
Can I equip different items in the left and right ear independently?
Yes. The resolver matches archetype AND slot together. A Black Earring in LeftEar and a Gold Earring in RightEar resolve to separate variants independently with no interference.
Can the same item look different on different characters?
Yes. One AccessoryItem holds multiple AccessoryVariantDefinition assets each tagged to a character archetype. The resolver picks the matching variant automatically.
How do I support Black, Gold, Platinum versions of the same mesh?
Add AccessoryMaterialVariant to the prefab root with your materials in the Variants array. Set Material Variant Index on each AccessoryVariantDefinition to 0, 1, or 2. The controller applies the correct material immediately after instantiation.
My accessory material is not changing — what should I check?
Three things: (1) AccessoryMaterialVariant is on the prefab root, not a child. (2) The Variants array has all materials saved — open the prefab in Prefab Mode, assign all three materials, and save. (3) Each AccessoryVariantDefinition SO has Material Variant Index set and saved individually with Ctrl+S — batch multi-select may not save all changes correctly.
Do accessories follow animations automatically?
Yes. Accessories are parented directly to the target bone at runtime. Unity's transform hierarchy propagates all movement — animations, physics, root motion, cutscenes — automatically with no extra logic.
Does this work with multiple characters simultaneously?
Yes. Each character has its own AccessoryController with independent state. No shared global state between characters. The demo shows four characters simultaneously.
Is the save module required?
No. AccessorySaveModule is entirely optional. Omit it and nothing is persisted. Subscribe to OnEquip/OnUnequip events to hook your own save system if preferred.
